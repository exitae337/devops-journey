Допустим создали мы приложение. Как же нам воспользоваться системой контроля версий?

Для начала необходимо создать репозиторий - удаленное хранилище нашего проекта. После в директории нашего проекта при помощи консоли вводим команду

``` bash
git init
```

Данная команда инициализирует локальный репозиторий на нашей машине.
После добавляем все наши измененные файлы (или если необходимо, определенные) данной командой:

``` bash
git add .
```

Данная команда добавит все существующие измененные или добавленные файлы проекта в индекс для дальнейшей их "отправки" в удаленный репозиторий.

После этого выполняем первый коммит - снимок состояния нашего проекта в системе контроля версий Git. Для этого служит данная команда:

``` bash
git commit -m "Мой первый коммит!"
```

*Флаг `-m` для ввода сообщения - что мы хотим "закоммитить". Удобно для того чтобы потом понимать что мы "отправляли" и что мы делали с нашим проектом. Описание сразу с консоли.*

*Флаг `-a` используется для того чтобы добавить все ОТСЛЕЖИВАЕМЫЕ git файлы в коммит. То есть мы можем не вводить команду `git add .`, но в коммит добавятся только те файлы, которые git уже отслеживал. Новые созданные файлы туда не попадут!*

*Флаг `-am` совмещает два предыдущих флага вместе - и добавляем измененные файлы и подписываем коммит одновременно.*

*Флаг `--amend` нужен для того, чтобы исправить **последний** наш коммит. Мы можем добавить файлы, которые мы забыли, в предыдущий коммит. То есть новый шаг истории не создается - мы перезаписываем предыдущий шаг.*

*Также есть еще два флага: `--no-verify` для пропуска автоматической проверки кода - полезно если перед коммитом у нас например настроен запуск тестов или линтера, который временно нужно опустить для скорости; `--allow-empty` разрешает создать пустой коммит. По умолчанию так делать git запрещает. Такое нужно например для проверки работы сборки кода.*

После выполнения коммита, необходимо связать удаленный репозиторий с нашим локальным. Для этого используем команду: 

``` bash
git remote add origin https://github.com/your-login/repo-name.git
```

Ссылку на твой удаленный репозиторий можно найти на GitHub после создания репозитория. Также можно подключаться не только по https (как выше), но и через ssh, что безопаснее и удобнее. Для этого надо один раз создать SSH-ключ на локальной машине и добавить его в профиль на GitHub. Пароль от GitHub больше вводить не придется.

После этого смотрим в какой ветке мы назодимся. Главная ветка называется **master** или **main**. Для этого можно ввести команду: 

``` bash
git branch
```

Или чисто получить название ветки:

``` bash
git branch --show-current
```

После этого заливаем изменения на удаленный репозиторий на GitHub:

``` bash
git push -u origin main
```

Флаг `-u` тут нужен для того чтобы установить постоянную связь между локальной веткой и веткой на удаленном репозитории. То есть командой выше мы говорим: "Отправь изменения ил локальной ветки main в удаленную ветку main на сервере origin и свяжи их между собой". Это выполняется при первом push и дает преимущества для всей дальнейшей работы. Например сокращение будующих команд. Достаточно писать `git push` и  `git pull` вместо долгих `git push origin main` и для `pull` соотвественно. Также такой первый пуш дает информативный `git status`.  Данная команда позволяет узнать: опережает ли ваша локальная ветка удаленную (нужно сделать push при необходимости) или отстает от актуальной (кто-то другой закгрузил код и нужно сделать `git pull`). Еще один важный момент: если ветки не связаны, команда `git pull` может выдать ошибку с требованием указать, из какой именно удаленной ветки вы хотите забрать изменения. Флаг `-u` решает эту проблему раз и навсегда для **текущей** ветки.

То есть флаг `-u` используется один раз при самой первой отправке изменений новой ветки на сервер. Все последующие разы можно работать без данного флага.

Таким образом наш workflow выглядит так:
1. Добавляем (git add)
2. Коммитим (git commit)
3. Пушим (git push)
